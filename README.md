**Han1meViewer-revive** 是基于 [YenalyLiew/Han1meViewer](https://github.com/YenalyLiew/Han1meViewer) 的社区修复分支。

上游项目已停止维护。本分支针对目标站点的新版页面重构了网页解析、搜索参数和部分接口，使应用可以继续浏览新版页面。

当前版本：**1.0.1**（2026-11-25）。新增功能与修复说明见[1.0.1 更新日志](changelogs/1.0.1.md)，历史版本见 [changelogs](changelogs/)。

> 本项目仅供学习 Android 开发与网页解析技术使用，不提供任何影片内容、下载源或使用教程。  
> 内容仅面向成年人，请遵守你所在地区的法律法规。

## 下载

推荐直接从 [Releases](https://github.com/SuperHeiHun/Han1meViewer-revive/releases/latest) 下载最新 APK：

1. 打开 Releases 页面。
2. 在最新版本的 **Assets** 中下载 `Han1meViewer-revive-v*.apk`。
3. 安装即可；如果已安装原版 Han1meViewer，可能需要先卸载。

CI 构建也会在 Actions 中保留一份构建产物作为备份：

1. 打开 [Actions](https://github.com/SuperHeiHun/Han1meViewer-revive/actions/workflows/ci.yml) 页面。
2. 选择最新一次成功的 `CI` 构建。
3. 在页面底部下载 `Han1meViewer-revive-<commit>` 构建产物（zip）。
4. 解压后得到 `Han1meViewer-revive-v*.apk`，安装即可。

也可以手动触发构建：进入 Actions → `CI` → `Run workflow`。

> 如果你是刚 Fork 本仓库，请先打开 Actions 页面启用工作流；若推送后没有自动运行，可手动执行 `Run workflow`。Fork 仓库只会上传 Actions Artifact，不会自动发布 Release。

## 本次修复内容

- 适配新版首页结构，恢复“最新上市”“最新上传”“裏番”“Motion Anime”“3DCG”“他们正在看”等栏目。
- 新版首页已移除“中文字幕”“本日排行”“本月排行”，改为通过搜索接口并发补齐，每栏显示前 12 项。
- 重写普通搜索、类型（genre）搜索、相关视频和播放列表解析。
- 搜索参数改为新版站点的 `date`、`duration`、`tags[]` 组合，移除已失效的 `year`、`month`、`brands[]`。
- 新增第 7 组搜索标签「情境场所」，并更新全部搜索选项为当前站点数据。
- 修复视频页标题、观看次数、上传日期、点赞数、标签、社团信息和播放源解析。
- 修复视频详情页作者头像解析，优先显示真实头像，兼容旧版结构与默认头像回退。
- 修复评论、回复、子评论 ID 解析，避免未登录状态下回复时崩溃。
- 适配评论区新版 `comment-item-block` 结构，并支持 offset 分页自动加载更多评论。
- 修复预览页左右切换按钮检测。
- 删除已返回 404 的 `deletePlayitem` 接口，改用 `playlist/delete`。
- 恢复“关于”页面，并修复设置中“关于”无法点击的问题。
- 检测到站点 Cloudflare 人机验证时，应用会弹窗引导手动完成验证；验证页保持 WebView 默认 UA（Turnstile 要求会话内 UA 与浏览器特征一致），完成后同步 `cf_clearance` 等 Cookie 并自动重试原页面。
- 重试时自动切换到验证时使用的 UA，并补齐浏览器请求头（Client Hints、`Sec-Fetch-*`），避免再次被 Cloudflare 拦截。
- 同步过的 Cookie 会本地保存，验证仍有效时应用重启无需再次验证。

## 功能

- 首页栏目、每日/每月排行、中文字幕筛选
- 关键词搜索、类型搜索、标签/日期/片长筛选
- 视频播放、清晰度选择、播放列表、相关推荐
- 播放器中间区域上划进入全屏，保留横划进度、左右亮度/音量和长按倍速手势
- 本地屏蔽标签与作者：首页、搜索和相关推荐自动过滤，支持设置页管理和详情页快捷添加/解除
- 评论查看与回复
- 收藏、稍后再看、自定义播放列表、订阅
- 本地收藏与待播放：无需登录、持久保存，独立于网站账号；待播放按加入顺序排列
- 观看历史、下载管理、本地关键帧
- 下载文件夹可通过系统选择器修改，已有任务保留原位置
- 本地文件 / WebDAV 分项备份恢复，以及停止新增搜索和观看历史的隐私模式
- 简繁体与英文界面

### 增强播放手势（当前源码，尚未发布）

> 以下第一期增强不包含在已发布的 `v1.0.1` APK 中；当前未提升版本号，也未建立新版本日志。已完成实现、静态检查和 Debug 构建，并在模拟器上保留数据覆盖安装；新增回归用例未运行，尚未进行设备功能验证。

- 进入“设置 → 播放器设置 → 播放手势”配置。升级默认保持**全区域双击播放／暂停**和**长按速度＝当前播放速度 × 原有倍率**；旧的长按倍率不会被当作绝对速度重新解释。
- 双击可选择播放／暂停、左右半区快退／快进、增强三区操作或关闭。增强模式为左 35% 快退、中间 30% 播放／暂停、右 35% 快进；跳转步长可选 5 / 10 / 15 / 30 秒，同一区域继续点按会累计，并显示累计偏移和目标时间。未知时长时不跳转，但仍可播放／暂停；暂停时跳转后保持暂停。
- 长按可选择原有相对倍率、固定临时速度、长按后左右滑动变速或关闭。后两种模式默认从绝对 2.0× 开始，可设为 0.5×～4.0×，横滑按 0.1× 调整；放开或取消后恢复手势开始前的速度，不保存临时倍速，也不替换原来的常驻速度选择。
- 横滑进度、左侧亮度、右侧音量可独立开关并分别调节灵敏度；灵敏度数值越小，变化越快。进度手势沿用旧灵敏度映射，只预览目标，松手提交一次跳转，取消不提交。画面提示层显示进度、亮度、音量或临时倍速，不拦截控制按钮及底部进度条。
- 手势提示以短暂淡入、轻缩放和小幅位移动画出现；双击累计跳转与数值变化提供轻量脉冲反馈，数值即时更新、不做延迟计数。进度、亮度和音量提示保留原有短暂停留后淡出，长按结束、取消、切换视频或离开时仍立即清理；连续操作会撤销旧的隐藏任务，不改变实际跳转、音量、亮度或倍速逻辑。
- 单击仍显示／隐藏控制栏，中间三分之一区域上划全屏继续复用原有全屏按钮，优先于该区域的亮度／音量调节。统一方向锁定，一次触摸不混用多个手势；多指介入、失焦、离开或切换视频／清晰度会取消未提交操作、清理延迟任务并恢复临时速度。连续跳转以待确认目标累计，避免内核位置快照更新较慢时丢步。
- 保留 JZVD、ExoPlayer 和系统 MediaPlayer，以及在线、旧文件和 SAF 离线播放流程；新设置包含在可移植“应用设置”备份中，并校验枚举、类型和数值范围。新增界面文案提供简体中文、繁体中文和英文。交互参考 Only Player，未迁移其 Compose UI 或引入新播放器。
- 双指缩放／平移、画面重置与触摸锁留待第二期；本期不包含滑动切换视频、联网缩略图预览或持续实际跳转。

### 全局播放设置与横竖屏播放列表（当前源码，尚未发布）

- 横屏和竖屏播放器顶部均提供齿轮设置入口，打开独立的播放器设置面板，只包含**播放模式、比例选择、自动旋转**，不套用应用原有的设置页。三项均全局保存，切换视频、退出重进以及在线／离线播放共用，也包含在可移植应用设置备份中。
- 播放模式包含“列表循环、循环播放、播完暂停”：列表循环按当前系列的正序／倒序播放，末项回到首项；无系列或离线视频视为单项列表循环。循环播放只重复当前视频；播完暂停保留末帧，不切换也不重播。默认播完暂停；旧版已开启自动连播的偏好迁移为列表循环，关闭则迁移为播完暂停。原设置页和横竖屏列表中的自动连播开关已移除，不再与播放模式并存。
- 比例可选原始比例（适应画面）、16:9、4:3、拉伸铺满、等比裁剪铺满，默认原始比例。修改只调整视频输出尺寸，不更换画面 Surface、不重启媒体，也不改变控制按钮和手势区域。
- 自动旋转默认关闭；开启后依据实际视频宽高（不是封面）选择横竖屏，首次播放、手动选片和列表循环的下一项均生效。横向视频自动进入横屏全屏；竖向视频使用竖屏，已在全屏时保留全屏容器。未知尺寸或正方形保持方向不变；开启时不会与重力感应方向监听争抢，关闭后保留原有手动全屏及感应行为。
- 横屏列表与详情页的系列影片使用同一份网站系列数据，显示封面、标题、当前位置和正在播放标记，并自动定位当前项。有系列资料时显示入口；这不是网站账号的自定义清单，也不会把推荐、本地待播放或历史混入连播队列。
- 横屏清单和竖屏系列列表上方继续保留“播放顺序”标题与“正序／倒序”单选项。正序保持网站原顺序，倒序仅反转，不按标题或编号重新排序；横竖屏列表使用同一顺序，切换后同步显示，并保留当前播放标记。设置面板中的播放模式独立于顺序控制，不能将顺序切换误当作循环开关。
- 顺序同样全局保存并可备份；修改播放模式或顺序不立即切片、不暂停或重启当前播放，下次正常播完按最新规则处理。无系列或离线播放时不显示系列顺序控制，但播放器设置入口与全局播放模式始终可用。
- 排序切换补充 7 个顺序／连播边界／备份校验用例和 2 个偏好设置用例，均未运行；已完成 Debug 构建并在 `emulator-5554` 保留数据覆盖安装，未启动应用或执行设备功能验证。
- 横竖屏顺序控件复用同一布局与绑定逻辑，竖屏通过随视图生命周期注册／注销的偏好监听同步设置，避免控件回收后状态过期或重新绑定时误改偏好。独立设置面板同样避免初始绑定、后台恢复或偏好同步误触设置写入；旧备份中的连播值兼容转换为播放模式，新备份不再导出旧开关。
- 只在前台视频正常播完时应用循环／下一项规则；缺少当前系列项时不猜测其他视频，不自动选推荐视频。失败时停留供重试，不跳过失败项；保留原有移动数据播放确认，后台、加载切换时取消尚未执行的旧视频重播。
- 点击竖屏系列、相关推荐或横屏列表，以及列表循环，都会复用当前 `VideoActivity` 和播放器；自动旋转关闭时保留原横屏状态，不再叠加新的播放活动。切换前释放旧媒体并取消临时手势／未提交跳转，刷新标题、封面、详情、评论、关键帧与本地收藏状态；旧请求与旧操作结果不能覆盖新视频，返回键不再逐个回退已切换的影片。返回原列表的行为不变。
- 本次新增 14 条简中、繁中、英文文案和 38 个回归用例，覆盖全局播放规则、循环边界、比例计算、方向判断、偏好持久化／同步、旧备份迁移、独立面板与播放器切换，并调整原有连播控件用例。已完成静态检查、Debug 构建和 `emulator-5554` 保留数据覆盖安装；未运行或单独编译测试源码、未启动应用验证。应用版本、数据库、依赖及已发布 `changelogs/1.0.1.md` 不变，设备功能验证由使用者负责。

### 搜索与历史

- 首页右上角搜索按钮与侧边栏的“搜索历史”统一打开搜索历史页。页面内输入文字可即时筛选已有记录，点击搜索按钮或键盘搜索键发起网站搜索；无匹配历史时也可直接搜索。清空输入会恢复完整历史，输入和光标位置会在页面重建时保留。
- 搜索框下方提供空白搜索提示：不输入内容，直接点击搜索可查看最新上传，并在结果页使用高级搜索筛选；提示支持简体中文、繁体中文和英文。
- 历史记录按最近搜索优先排列，点击可重新搜索，右侧叉号删除单条，工具栏清空全部时需要确认（不受当前筛选影响）；与观看历史独立，不需要登录。继续复用 `history.db`，不会删除升级前的记录。
- 输入标签前缀时显示本地标签补全建议，支持简体、繁体、英文、大小写与全半角，也支持英文多词标签；输入 `#` 可浏览建议，横向滑动可查看更多。点击建议插入明确的 `#"标签"` 搜索语法，只替换光标所在片段，保留前后的标题和其他标签，忽略已选标签；双引号包围的标题不参与补全。补全使用内置标签表，不发起网络请求。
- 已移除原搜索结果页的历史下拉、历史入口按钮、展开收起动画、监听与专用查询/删除接口；结果页和高级搜索继续保留，播放页标签、作者及首页分类仍可直接打开对应结果。统一的首次页搜索历史保存逻辑继续保留。
- 搜索框支持用空格组合多个完整标签，例如 `1080p 60FPS`；标签与标题可混合，例如 `1080p 60FPS 作品名`。标签转换为网站的 `tags[]` 条件，其余文字仍作为标题关键词，与高级搜索中已选标签合并，不改动原始结果分页或屏蔽规则。
- 标签识别支持内置标签表中的简体、繁体与英文名称，忽略大小写和全半角；英文多词标签优先匹配完整名称。未知标签可以写成 `#标签名`，含空格时使用 `#"Custom Tag"`；标签会去重。
- 普通标题仍可直接输入；若标题文字恰好与标签同名，用双引号强制按标题搜索，例如 `"ASMR"` 或 `1080p "A title with spaces"`。
- 从播放页点击标签会以明确的标签条件搜索，并写入搜索历史，不必再次点击搜索按钮。观看历史改为在视频资料加载成功后、展示可交互详情前保存，不再依赖 Activity 界面回调；跳转搜索或离开页面不会中断已经开始的本地保存。离线下载视频仍不计入观看历史。
- 历史保留本次输入文字（包含多标签与标题语法）；重放不会恢复当时另选的分类、排序等高级选项。新增界面文案提供简体中文、繁体中文与英文。

### 下载路径

- 进入“设置 → 下载设置 → 下载路径”，选择可读写、支持随机写入的本地文件夹，也可恢复默认的 `Download/Han1meViewer-revive` 路径；长按可复制当前路径或授权文件夹 URI。选择时会检查持久授权、文件读写与定位能力，失败保留原设置，不申请所有文件访问权限。
- 自选目录使用系统 SAF 授权，视频仍存入其下的 `hanime_download/<视频编号>/`。新任务在加入队列时固定目标目录；切换路径仅影响之后新增的任务，已有下载、暂停 / 排队任务及其重新下载继续使用原文件位置，不自动迁移或删除旧文件，也不会在目录失效时悄悄改存别处。切换或恢复默认路径时保留旧目录授权，供旧任务续传、播放和删除。
- 封面与离线资料跟随任务的实际视频位置读取和保存，兼容升级前的文件地址和新目录的内容 URI。删除与重新下载仅操作当前清晰度，不再递归删除整个视频目录；仅在没有其他文件时清理共享资料。下载路径及目录授权不进入可移植应用设置备份，版本号、下载数据库结构和依赖不变。
- 系统禁止选择的目录或不支持随机读写的提供器不可用；可选择允许访问的本地子目录。移动 / 删除文件、移除存储设备或撤销授权后，需恢复原位置 / 授权，或删除旧任务后在新目录重新添加。新增三语提示与存储回归用例；已完成 Debug 构建与保留数据覆盖安装，新增测试尚未运行，功能验证由使用者自行完成。

### 备份与恢复

- 进入“设置 → 备份与隐私 → 备份与恢复”，可分别勾选**观看历史、搜索历史、应用设置、本地收藏、本地待播放**。同一组勾选同时用于导出和恢复；不会改动未勾选或备份中缺少的类别，包含但为空的类别也不会清空已有数据。
- 本地导出 / 恢复使用系统文件选择器，可自行选择设备存储或文件提供器；无需新增存储权限。格式为带版本标记的 JSON，单文件上限 **20 MiB**、合计最多 **100,000 项**，导入时先校验整个文件，再显示当前选中且文件中包含的项目数量，确认后才恢复。
- 历史和本地列表采用**合并去重**，保留已有相同项目的资料；搜索文字保留原有多标签 / 标题语法，恢复后仍可点击重搜。本地列表保留原加入时间和排序规则，不影响网站在线列表，不自动下载视频。
- 应用设置只备份可移植设置白名单，包括播放器、网络、下载并发 / 限速、关键帧、视频语言、更新偏好和隐私模式，以及标签 / 作者屏蔽规则。恢复覆盖同名设置、合并屏蔽规则；切换网站域名可能退出登录，部分设置需重启应用后生效。**不包含登录凭据、Cookie、WebDAV 配置、下载文件、下载路径或关键帧数据文件。**
- WebDAV 请先在服务器建好目录，再填写该目录下的**完整 HTTPS 文件地址**（必须包含文件名，如 `https://example.com/dav/backup.json`）。使用 HTTP Basic 认证，可填写应用专用密码或按服务器要求留空；上传使用 PUT，恢复使用 GET，不自动创建目录、不跟随重定向，也不绕过证书校验。上传前会确认，已有同名文件会被覆盖；没有自动备份、定时同步或后台上传。
- WebDAV 地址和账号密码通过 Android Keystore 的 AES/GCM 密钥在本机加密保存，并从系统云备份和设备迁移中排除；更换设备需重新配置。配置无法读取时，可在配置对话框清除后重新填写。WebDAV 使用独立客户端，不发送网站 Cookie、Cloudflare 请求头或网站登录凭据。
- **备份文件本身未加密**，可能包含观看记录、搜索词、收藏和网络设置，请妥善保管，仅使用可信文件及服务器。恢复按历史数据库、本地列表数据库和设置分别处理，不是跨存储的全局事务；失败时可能已有部分项目合并，可重试而不会产生重复记录。当前尚未完成真实 WebDAV 服务器联调。

### 隐私模式与卡片菜单

- “设置 → 备份与隐私 → 隐私模式”开启后不再新增搜索和观看历史，重启后保持；关闭后仅恢复记录后续请求，不补记隐私期间或跨越开关切换的延迟请求，也不删除旧历史。原有搜索入口、标签补全和非隐私模式的历史保存修复继续保留。
- 隐私模式不影响手动收藏、本地待播放、下载或用户确认的备份恢复；导出仍会包含所选的旧历史。它不是网络匿名模式，不会隐藏发往网站 / WebDAV 的请求，也不会清理系统键盘、文件提供器或服务器保存的信息。
- 长按普通视频卡片、观看历史、本地列表或在线列表中的视频，可复制分享信息、加入 / 移出“稍候再看（本地）”、选择屏蔽当前视频的标签 / 作者，或直接进入屏蔽设置。本地待播放已有的移除操作及历史、在线列表原有的删除确认继续保留；本地“稍候再看”不会修改网站在线待播放。
- 打开卡片的标签 / 作者屏蔽菜单时，资料不足会按需读取详情并复用既有缓存，不触发观看历史；读取失败仍可进入屏蔽规则管理。新增界面文案提供简体中文、繁体中文和英文。

### 更新设置

- 更新弹窗的更新说明支持 Markdown：标题、粗体/斜体、删除线、引用、有序/无序列表、任务列表、行内代码/代码块、表格和可点击的网页链接，保留普通文本换行；长内容仍可滚动，样式跟随弹窗主题。
- Markdown 使用原生文本渲染，不使用 WebView、不执行 HTML/脚本、不自动加载远程图片（仅显示替代文字）；链接仅允许打开 HTTP/HTTPS 网页，不改变更新下载、安装与自动检查设置。
- 进入“设置 → 更新”，可开启“禁用自动更新”。开关默认关闭，保留原有的启动自动检查行为；开启后不再自动检查版本或弹出更新提示，重启后仍生效。
- 开启后会取消正在进行的自动检查；切换更新渠道也不会自动发起检查，更新弹窗间隔设置暂时不可用。
- 仍可点击“检查更新”手动检查并选择是否下载、安装，正式版与 CI 渠道选择不受影响；Firebase Remote Config 继续保留用于更新渠道配置，不包含统计或监控。

### 本地列表

- 视频简介页点击“加入本地收藏”或“加入本地待播放”，再次点击可取消。
- 侧边栏“本地列表”可查看两个列表，点击视频播放、长按打开菜单后确认移除，也可从工具栏清空当前列表。
- 本地收藏和待播放互相独立，同一视频可同时加入；重新打开应用后仍保留，不会同步或修改在线列表。
- 待播放不会在打开视频时自动移除；列表仅保存视频信息，不会自动下载视频。
- 已移除使用情况统计、页面与搜索埋点、性能监控及自动崩溃上报。Firebase 仅保留更新渠道使用的 Remote Config。

### 屏蔽标签与作者

- 进入“设置 → 屏蔽标签与作者”，可添加完整标签名或作者名，点击已有规则可解除屏蔽。
- 屏蔽图标跟随主题颜色，兼容深色模式。
- 视频简介页的“屏蔽标签与作者”按钮可直接选择当前视频的作者或标签；长按标签可选择复制或屏蔽，长按带作者的视频卡片也可快捷屏蔽作者。
- 按完整名称精确匹配，忽略大小写、全半角与首尾空白；标签可带 `#` 前缀。不通过标题子串推测标签，也不自动转换简繁名称，请以网站显示的名称为准。
- 规则只保存在本机，无需登录，重启仍生效，不同步到网站。首页（包括视频横幅）、搜索与相关推荐会自动重新过滤；解除规则后可恢复已加载且不再命中其他规则的视频。
- 不删除或过滤用户已保存的收藏、待播放、历史、系列列表或下载，也不阻止通过链接主动打开视频。
- 视频卡片通常缺少完整标签；启用规则或主动打开卡片的标签 / 作者屏蔽菜单后按需额外读取详情页，最多 3 个并发请求，成功结果内存缓存 30 分钟（最多 512 项）。未启用规则且未主动打开该菜单时，不会为屏蔽功能发起额外请求。
- 资料尚未确认或读取失败的卡片暂不展示，可下拉刷新重试；不会因过滤后为空误判网站已无更多数据，搜索页提供“加载下一页”按钮。
- 这些改动从 `v1.0.1` 起提供，旧版 `v1.0.0` Release 不包含此功能。

## 构建

### 环境要求

- JDK 21
- Android SDK 35
- Windows、macOS 或 Linux

### 本地构建

```bash
git clone https://github.com/SuperHeiHun/Han1meViewer-revive.git
cd Han1meViewer-revive

# 本地没有真实 Firebase 配置时，可以使用仓库里的示例配置
cp app/google-services.json.example app/google-services.json

# Debug 包
./gradlew assembleDebug

# Release 包
./gradlew assembleRelease
```

Windows 下把 `./gradlew` 换成 `gradlew.bat`。

构建产物：

- Debug：`app/build/outputs/apk/debug/Han1meViewer-revive-v1.0.1-debug.apk`
- Release 1.0.1：`app/build/outputs/apk/release/Han1meViewer-revive-v1.0.1.apk`
- Release：`app/build/outputs/apk/release/Han1meViewer-revive-v*.apk`

### 签名说明

本分支使用仓库中的公开测试密钥 `app/keystore/Han1meViewer-revive.jks` 为 Release 包签名，方便 Actions 在没有额外配置的情况下直接出包。

- 该密钥仅用于社区测试构建，**不适用于 Google Play 或任何正式分发**。
- 如需使用自己的密钥，请替换 `app/keystore/Han1meViewer-revive.jks`，并修改 `app/build.gradle.kts` 中的 `keyAlias` 和密码。
- 由于签名密钥与上游不同，安装本分支前可能需要先卸载原版 Han1meViewer。

### GitHub Actions

工作流文件：`.github/workflows/ci.yml`

- 推送代码或手动触发时构建 `assembleRelease`。
- 在 `SuperHeiHun/Han1meViewer-revive` 仓库中，`feat/new_download` 分支构建成功后会自动发布 GitHub Release：先创建 draft，上传 APK，再正式发布。
- 从 1.0.0 起，正式版使用 `1.0.0` 形式的版本名和 `v1.0.0` 形式的 Release tag；Android `versionCode` 仍按构建时间递增。
- 每个版本的更新日志仅保存在 `changelogs/<版本号>.md`，不再维护根目录索引；Release 说明直接读取对应版本文件，文件缺失或为空时停止发布。重复构建不会覆盖已发布版本；新版本需更新版本号、新增独立日志并更新 README 的当前版本链接。
- 应用内更新检测兼容新版本标签与旧版 `v0.16.0+261122058` 格式，不会对同一正式版本反复提示更新。
- Fork 仓库只上传 Actions Artifact，不会自动发布 Release。
- 默认使用 `app/google-services.json.example` 作为 Firebase 配置占位，因此全新 Fork 也能直接出包。
- 使用占位配置时，构建会自动关闭 Remote Config，避免无效 API Key 导致启动崩溃；应用内更新会直接检查 GitHub Releases。
- 如需真实 Firebase 配置，在仓库 Secrets 中添加 `HA1_GOOGLE_SERVICES_JSON_BASE64`（`google-services.json` 的 Base64 内容）。

### 本地推送脚本

- 本机根目录可使用 `push.ps1`：运行 `.\push.ps1` 推送当前分支到 `origin`，或运行 `.\push.ps1 -WhatIf` 预览推送目标。
- 脚本要求工作区干净，仅推送已提交代码；不自动提交、不强推、不推送标签、不保存凭据。推送 `feat/new_download` 后，由上述 CI 构建并按版本发布，不另行覆盖已有 Release。
- `/push.ps1` 已加入 `.gitignore`，仅保存在本机，不随仓库分发；新克隆的仓库不包含该脚本。
